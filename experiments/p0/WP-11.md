| HLE | `test` | 2,500 (docs; gated) | `answer` + `answer_type` | 2,500 |

Consequences encoded in the loader:

* BrokenMath/BrokenArXiv return **0 eligible rows** for answer-scored metrics. They are skipped, not crashed on; the
  count lands in `eligible_n.json` as `n_skipped_no_answer`. They remain available as appendix premise-rejection sets
  (the raw HF rows still hold `problem`/`solution`); they are not retrieval-trust datasets.
* A `train` split is refused unless the spec records it as the release's benchmark (`train_is_benchmark: true` for
  GPQA and BrokenArXiv). BrokenMath loads its `benchmark` split.
* `answer_type` is copied to the question dict whenever present (HLE MCQ vs exact-match).

## Stratified sampling

`rows[:cap]` is gone. `stratified_sample(rows, cap, seed=...)`:

1. Strata = first present field in `category`, `subject`, `raw_subject`, `High-level domain`, `domain`, `subdomain`,
   `topic`, `field`, `question_type`; rows with none go to `unstratified`.
2. One seat per stratum is reserved when `cap >= #strata` (tiny categories cannot disappear).
3. Remaining seats are proportional to stratum size by largest remainder; ties break on stratum size then name.
4. Within a stratum, a `random.Random(seed)` sample of positions; selected rows are re-sorted into dataset order.
5. Seed comes from `configs/datasets.yaml: sample_seed` (1), overridable by `load_dataset(seed=...)`; it is separate
   from the run seed so every arm sees the same paired question set.

Documented per dataset: MMLU-Pro → `category` (14 categories), GPQA → `Subdomain` (or `High-level domain`), HLE →
`category`, BrokenMath → `question_type` (`proof`).

## `eligible_n.json`

`write_eligible_n(rows, path, ...)` writes the file (a directory expands to `eligible_n.json`). `load_dataset` writes
it when `eligible_path=` is passed or `TRUSTCAL_ELIGIBLE_DIR` is set:

```text
$ TRUSTCAL_ELIGIBLE_DIR=results/datasets python scripts/run_experiment.py --arm B3 --dataset mmlu_pro
results/datasets/mmlu_pro/eligible_n.json
```

Payload (synthetic 6-row fixture, exact output of `write_eligible_n`):

```json
{
  "dataset": "mmlu_pro",
  "split": "test",
  "revision": "b189ec765aa7ed75c8acfea42df31fdae71f97be",
  "requested": 6,
  "n_available": 12032,
  "n_skipped_no_answer": 0,
  "sample_seed": 1,
  "n_eligible": 6,
  "strata": {
    "biology": 2,
    "business": 1,
    "computer science": 1,
    "math": 1,
    "physics": 1
  }
}
```

The real run reports `requested: 1000`, `n_eligible: 1000` and the true stratum counts (MMLU-Pro has 14 categories).

`n_eligible` is the sampled, answer-scored count; `n_available` is the post-skip corpus size. This is the number the
paper reports instead of "1,000 per dataset".
