## 1. What was wrong

- `DebateRunner` called `classify_claim` directly (`debate.py:64`), so no `Verifier` could be
  injected and the judged passages were the raw retrieval result, not the passages the prompt showed.
- The injection was appended to `AGENT_SYSTEM` and persisted into round 3; the "consensus" was the
  panel's own majority with no source label.
- B8 had trust + retrieval but no injection path; the injection arm had no trust, so the treatment
  (trust + pressure) was never exercised together.

## 2. What changed

| File | Change |
|---|---|
| `orchestrator/debate.py` | `verifier: Verifier \| None` field (default `LexicalVerifier()`); `self.verifier.verdict(claim, passages)` replaces `classify_claim`; `select_evidence` before judging; flat schema-v2 `verdicts[]`; one-shot round-2 user injection; `injection_arm/source/template` fields |
| `orchestrator/injection.py` | strict 2/3 majority, `consensus_source`, authority/peer/neutral/none arms, 3 paraphrases, length-matched neutral arm, `delivered`/`arm` logging |
| `agents/prompts.py` | `{trust_line}` slot in initial/revision/evidence prompts; `trust_line()` helper (WP-13) |
| `mock_vllm.py` | detects the P0-9 user-turn marker; keeps a revised minority position across the injection-free round 3 |

### Verdict record (schema v2)

One entry per distinct claim, per scored round, for agents whose evidence is non-empty:

```json
{
  "agent": 0,
  "round": 2,
  "claim": "alpha reduces risk",
  "passages": ["alpha reduces risk in the randomized trial"],
  "scores": [0.79],
  "evidence_ids": ["p0"],
  "verdict": "supported",
  "verifier": "lexical"
}
```

`trust_rounds[]` keeps the old per-round `support`/`harm`/`n_claims` audit vector; `verdicts[]` is
the per-claim schema-v2 list. The record payload copies `verdicts`, `evidence`, `injection`,
`trust_trajectory` unchanged.
