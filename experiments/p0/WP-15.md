# WP-15 — analyze.py arm/dataset guard

**P0:** P0-11 (`analyze.py --dir` cannot silently pool arms).
**Wave:** 1. The guard is landed and tested; the manifest reproduction check lives in `runner.py` and lands in wave 2 (see `experiments/p0/WP-04.md`).

## What changed

`trustcal/scripts/analyze.py` now detects the arm and dataset of every loaded
record and refuses to pool more than one of either unless `--allow-pool` is
passed. One slice can be selected with `--arm` / `--dataset`; seeds of the same
arm/dataset still pool normally, because seeds are replicates, not conditions.

| Situation | Behaviour |
| --- | --- |
| One arm + one dataset (`--dir` or `--records`) | proceeds exactly as before, now printing the detected labels |
| Several arms and/or datasets, no flags | exit 2: `refusing to pool ...` with the detected lists and both remedies |
| Several arms/datasets with `--allow-pool` | proceeds, marks the output `(pooled)` / `"pooled": true` |
| `--arm`/`--dataset` selects one slice | proceeds on that slice only |
| `--arm`/`--dataset` not present | exit 2: `no records for arm/dataset ...` |
| Flags name an empty intersection | exit 2: `no records match arm=... dataset=...` |

Detection order for the dataset label: the record's own `dataset` key (if a
future schema adds one), then the `<arm>/<dataset>/seed<N>/` run layout, then
the `dataset-NNNN` question id. The arm comes from the record's `arm` key.
Neither fallback mislabels the existing run tree.

## CLI

```text
python scripts/analyze.py --dir results/B8/gpqa --json
python scripts/analyze.py --dir results --arm B8 --dataset gpqa
python scripts/analyze.py --dir results --allow-pool      # explicit pooling
```

single `--records` file backward compatibility (labels printed), seed pooling,
unknown arm, and an empty arm×dataset intersection.

## Notes

- `summary.json`/`--json` payloads gain `arms`, `datasets`, and `pooled`; the
  existing summary keys are unchanged.
- Output for a single-arm directory changes by two informational lines
  (`arms:` and `datasets:`); no metric value changes.
- Wave-2 follow-up (optional): pass `--manifest` to verify every record carries
  the run's `manifest_hash`, and refuse mixed hashes even with `--allow-pool`.
  The authoritative refusal already lives in `runner.py` via
  `manifest.check_resume`, so this is defense in depth, not a gate.
- Records currently have no `dataset` field (schema v2 is frozen without it).
  If the team adds one, detection uses it first; no analyzer change is needed.
