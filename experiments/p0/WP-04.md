## Record contract

`build_record(**fields)` fills the documented defaults: `None` for optional objects, `False` for the unscored correctness flag, `[]` for repeatable sections. It refuses to invent the two observed fields, so a missing one raises `TypeError` rather than writing a plausible lie:

- `final_answer` — the actual aggregation output;
- `evidence_introduced` — whether retrieval returned a passage that an agent saw.

`validate_record(record)` returns a list of readable errors (empty = valid). Rules:

| Rule | Detail |
| --- | --- |
| Required keys | all 24 schema keys; extra keys (`elapsed_s`, `pilot`, …) are allowed |
| Types | `seed` is a real int (not bool), `rounds`/`transcript`/`verdicts` are lists of dicts, trust vectors are lists of finite numbers |
| Gold | non-empty text; a bare A–J letter is rejected when `options_raw` is set (letters belong in `gold_letter_rendered`) |
| Final answer | present and non-empty; `final_answer_source` ∈ {`majority`, `weighted`, `single`, `oracle`} |
| Parser | `parser_version` non-empty |
| Permutation | when options are rendered, `option_permutation` has one original index per rendered option, each exactly once |
| Trust | `trust_for_positions` and every `trust_trajectory` row are non-empty, lie in [0, 1], and sum to 1 within `1e-6` |
| Trust status | values ∈ {`updated`, `abstained_unanimous`, `abstained_no_evidence`} |
| Rounds | at least one round, each with an `answers` list |
| Manifest | `manifest_hash` is carried verbatim (null until the runner stamps it) |

## Manifest contract

`build_manifest(config_paths, models_path, datasets_path, prompts_path, seed, temperature, *, run_config=None, created_at=None, code_commit=None)` returns:

`config_hash`, `config_files`, `model_checkpoints`, `prompt_hash`, `dataset_revisions`, `code_commit`, `temperature`, `seed`, `created_at`, plus `run_config` when supplied.

- `config_hash` hashes the config-file **contents** (identified by basename, so moving the repo does not invalidate a run) and the run-config values. `alpha`/`beta` live in `run_config`, so changing either changes the hash.
- `model_checkpoints` carries only result-affecting fields (`role`, `model`, `quant`, `max_model_len`, `extra_args`) for both phases.
- `code_commit` resolves `TRUSTCAL_CODE_COMMIT` → `git rev-parse HEAD` → `"unknown"`; no network.
- `manifest_hash` is sha256 over canonical sorted JSON of every field except `created_at` (wall clock) and an embedded `manifest_hash` (self-reference). Re-running the same config later therefore has the same result hash.
- `check_resume(path, current)` returns quietly for a fresh run directory, and raises `ManifestMismatch` naming every differing key (e.g. `computed: config_hash, run_config`) for an existing one.
- `write_manifest(path, manifest)` writes stable, diffable, sorted JSON.

## Wave-2 runner patch plan (5 lines, not applied)

1. In `run()`, after questions load and before the `done = {...}` resume scan: build the manifest with `build_manifest(["configs/experiments.yaml"], cfg.model_config, "configs/datasets.yaml", Path(__file__).parents[2] / "src/trustcal/agents/prompts.py", cfg.seed, cfg.temperature, run_config=_run_config_dict(cfg))`, set `manifest_path = run_dir(cfg) / "run_manifest.json"`, call `check_resume(manifest_path, manifest)`, then `write_manifest(manifest_path, manifest)` and keep `run_hash = manifest_hash(manifest)`.
2. Extend `_base_record(qid, question, arm, seed, manifest_hash)` to stamp `"manifest_hash": run_hash`; thread the same value through `single_agent_record`, `debate_record`, and `oracle_record` (all three call sites).
3. Where the record is assembled (after the arm branch, before `_append_record`), compute E's `final_answer(aggregation)` into `record["final_answer"]`, score it with A's `is_correct(..., options)`, and set `final_answer_source` (`single` for B1, `oracle` for B7, `weighted` when trust weights aggregation, else `majority`).
4. Immediately before `_append_record(path, record)`: `errors = validate_record(record)`; raise `ValueError(f"{qid}: invalid record: {'; '.join(errors)}")` so a bad record is never appended (crash-safe resume still holds).
5. In `_write_summary`, add `"manifest_hash": run_hash` and `"manifest": str(manifest_path)` to `summary.json`, and check resuming records all share `run_hash` before pooling them.

## Blockers / dependencies

- `eval/answers.py` has no `score_answer`/`Score` yet (WP-02) and `eval/metrics.py` has no `final_answer()` yet (WP-05). Wave 2 cannot make records valid without both; `validate_record` failing in the meantime is intentional.
- Schema v2 has no `dataset` key. `analyze.py` infers it from the `<arm>/<dataset>/seed<N>/` path or the `dataset-NNNN` question id; if the team wants it explicit, change `docs/agent/09_P0_INTERFACES.md` first.
- `configs/experiments.yaml` currently supplies alpha/beta defaults; the run config snapshot (`run_config=`) is what makes CLI overrides invalidate resume, so wave 2 must pass every results-affecting `RunConfig` field.
