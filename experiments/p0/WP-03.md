## 1. What was wrong

The old operator was `softmax(scores + α·support − β·harm)` → `clip(·, 0.1, 0.9)` → renormalize.
Renormalizing after the clamp pushes the winner back below the floor and above the ceiling:

- `update_trust([0.8, 0.1, 0.1], 0, 0)` returned `[0.5017, 0.2491, 0.2491]` — neutral evidence
  re-uniformized trust (reported in P0-5).
- Raw counts rewarded verbosity: `support [1,0,0]` → `0.4519`, `support [8,0,0]` → `0.8182`.
- The `[0.1, 0.9]` bound was asserted before renormalization, so the post-condition was false.

Operator (09 signature, `n_claims` optional for backward compatibility):

```
logit_i  = log(max(S_i, 1e-12)) + α · support_i / n_claims_i − β · harm_i / n_claims_i
trust_i  = project_simplex_with_floor(softmax(logit)_i, floor, ceiling)
```

- Softmax is applied **once**, in the log domain (max-subtracted, stable).
- `n_claims is None` → legacy raw-count path, so `runner.py:235`, `debate.py:110` (via
  `TrustState.update` / `trust_update`) and `state.py` keep working unchanged.
- `n_claims_i == 0` → no evidence term for that agent (`0/0` never evaluated).
- The projection solves `w_i = clip(x_i − θ, floor, ceil_eff)` for the exact θ: the piecewise-linear
  sum is evaluated at every breakpoint `x_i − ceiling`, `x_i − floor`, the crossing segment is
  located, and θ is solved in closed form on it. No bisection in the shipped path; the test suite
  compares against a 100-iteration bisection reference.

### Guarantee (also in the module docstring)

For `N` agents and `effective_ceiling = max(ceiling, 1/N)`, every output `w` satisfies simultaneously

```
min_i w_i      >= floor - 1e-9
|sum_i w_i - 1| <= 1e-9
max_i w_i      <= effective_ceiling + 1e-9
```

- The ceiling is relaxed to `1/N` only when `N · ceiling < 1` (no feasible vector exists otherwise).
- **N = 1 exception:** `[1.0]` is the only feasible vector, so the ceiling is inactive and `[1.0]`
  is returned even though `1.0 > ceiling`. The test uses the effective-ceiling bound.
- Infeasible policy (`N · floor > 1`) raises `ValueError` naming the constraint; there is no
  silent unnormalized return.
- Neutral evidence (`support = harm = 0`, or all `n_claims = 0`) is an exact identity for an
  already-feasible input (`softmax(log S) = S`), within `1e-12`. Infeasible inputs are projected,
  never renormalized.
- Claim counts cancel verbosity: `(support, harm, n_claims) × k` leaves trust unchanged.
