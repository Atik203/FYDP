## PENDING rule

A check is PENDING when the slice it verifies has not landed. Each check probes for the
capability before running its assertions, so a half-integrated branch can still gate the
slices that exist:

- `--allow-pending`: PENDING does not fail the run; exit 0 iff there is no FAIL and no ERROR.
- without the flag: exit 0 iff all 13 PASS.
- FAIL means a landed slice is broken. ERROR means the gate could not evaluate the check —
  usually an interface drift, so read the detail before editing anything.

The gate never edits another owner's code to make a check pass.
