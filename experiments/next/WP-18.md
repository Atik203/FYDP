## 1. Why this work package exists

P0 released a four-condition Core matrix: `B3`, `B4-matched`, `B8-no-trust`, and `B8` (`trustcal/configs/experiments.yaml`). That matrix is frozen at 4 conditions × 3 datasets × 2 seeds = **24 rows**; the P0 gate check 13 and `test_matrix_budget.py` assert 4 conditions and a **1,280 GPU-h** conservative cap. Those values must not change.

The six-arm target in `PRE_REGISTRATION.md` adds the two causal controls:

- **B8-placebo** — same evidence and prompts as B8, but the verdict labels are shuffled. It tests whether the effect comes from *evidence calibration* or from *any* re-weighting.
- **B8-oracle** — trust derived from gold information. It bounds the verifier bottleneck. It is not a deployable arm and is not B7 (B7 is the optional 3-sample GPT-6 Luna external-answer ceiling).

WP-18 must freeze both definitions before any Full run. The definitions are not frozen here; this file lists the decisions and acceptance conditions.

The Full matrix uses the Final stack and a separate `configs/experiments_full.yaml`. It must not be merged into `experiments.yaml`.

## 3. Semantics to freeze

### 3.1 Placebo shuffle unit and seed

The placebo must differ from B8 only in the verdict-to-claim assignment. It must preserve:

- the claim texts and their order,
- the retrieved evidence passages and the evidence display,
- the number of claims per agent and the number of verdicts,
- the multiset of verdict labels (support / harm / abstain, including confidence),
- prompts, decoding, rounds, and compute.

Candidates for the shuffle **unit** (choose one and record it):

- **A — agent-round claim vector.** Permute the verdict records across the claims of one agent in one round. This preserves each agent's evidence volume and changes only which claim gets which verdict.
- **B — debate-round claim pool.** Permute verdict records across all agents' claims in one round. This breaks both claim-level and agent-level alignment and is the stronger manipulation.
- **C — debate-level claim pool.** Permute across all claims in the debate. This is the strongest break but can move a verdict across rounds, which changes the round-wise trust trajectory.

WP-18 must state whether the unit is A, B, or C. The default candidate is A; it is not frozen by this record.

The shuffle **seed** must be deterministic and independent of outcomes. Freeze all of the following:

- the seed derivation, e.g. `hash(dataset, question_id, seed, round, agent)` or one seed per debate;
- whether one permutation is drawn per debate, per round, or per agent-round;
- the permutation algorithm and the tie-breaking rule;
- the resume rule: the same permutation must be reproduced from the stored seed/permutation hash, never redrawn;
- the no-op rule: if a unit has fewer than two verdicts, record `placebo_noop_reason` and do not silently fall back to B8.

Every placebo record must store `placebo_mode`, `placebo_unit`, `placebo_seed`, `placebo_permutation_hash`, and `placebo_noop_reason` (null when applied). The record must make it possible to reconstruct the permutation without re-reading model output.

### 3.2 Oracle definition

Two candidate definitions must be decided; they change the run count and the GPU envelope:

- **A — gold-answer trust (`oracle_mode: gold_answer`).** Trust is set from whether an agent's current/final answer matches the gold answer, bypassing the verifier. This is a non-deployable upper bound on what a perfect correctness signal could do. It can run on all three datasets, giving 36 Full rows / 1,440 GPU-h.
- **B — gold-evidence-only (`oracle_mode: gold_evidence`).** The normal verifier/trust path is kept, but gold evidence is supplied on SciClaimBench, where gold evidence exists. This is an evidence/verifier upper bound, not a gold-answer oracle. `B8-oracle` runs only on SciClaimBench, giving 32 Full rows / 1,280 GPU-h.

WP-18 must also freeze:

- whether trust is set once (initial/round 0) or recomputed every round;
- whether the gold answer is used only for trust, or also shown in the prompt;
- whether `B8-oracle` shares B8's prompts, source partition, and evidence volume;
- the record fields (`oracle_mode`, `oracle_gold_source`, `oracle_rounds_applied`);
- the exact SciClaimBench dataset key and revision used at v1.2.

Neither definition is asserted as final here. `PRE_REGISTRATION.md` v1.1 records the decision as pending WP-18.

## 4. Flags and config to add

### 4.1 `RunConfig`

Add two fields, default off so every released arm is byte-compatible:

```text
placebo_mode: "off" | "shuffle_verdicts"
oracle_mode:  "off" | "gold_answer" | "gold_evidence"
```

Required behavior:

- defaults are `off`; existing `RunConfig(...)` calls keep working;
- `placebo_mode != off` requires `arm == "B8"` and `use_trust is True`;
- `oracle_mode != off` requires `arm == "B8"`;
- `placebo_mode` and `oracle_mode` are mutually exclusive;
- `gold_evidence` requires a dataset with a gold-evidence field (SciClaimBench), and the key is rejected elsewhere;
- both fields enter the run manifest and every record; a resume with a changed value is a mismatch, not a silent continuation.

- six conditions: `B3`, `B4-matched`, `B8-no-trust`, `B8`, `B8-placebo`, `B8-oracle`;
- the selected `placebo_mode`/`oracle_mode` values and their frozen parameters.

`configs/experiments.yaml` stays at four conditions. `test_matrix_budget.py` and P0 gate check 13 keep asserting the Core matrix; WP-18 adds new tests for the Full config rather than editing those assertions.
